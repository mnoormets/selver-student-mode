# Roadmap

## Vision

By hour 48, deliver a browser demo in which one target user completes one valuable action and sees the outcome. At kickoff, the team will choose the user, problem, input, and outcome from the event brief and record them in the current task. The starter assumes a browser demo.

## MVP Features

- A clear starting screen and one complete input-to-result path.
- One realistic demo scenario using repeatable, locally available data.
- One representative invalid or empty input and a clear recovery path.
- A reset or restart for rehearsal, plus a shareable build and local fallback.

## Stretch Goals

Consider a live service, persistence, or a second user flow only after two successful demo rehearsals and if the team can still meet the submission deadline. Choose an external service earlier only if it is necessary to demonstrate the project's core value.

## 48-Hour Schedule

| Hours | Exit condition |
| --- | --- |
| 0–3 | Team confirms one demo scenario. Both machines run the same starter commit and agree on the input, output, and fixture. |
| 3–14 | Codex completes the happy path with local data. Lovable drafts UI in parallel if needed. Claude checks the first PR. |
| 14–28 | Integrate UI, handle one failure case, and verify the flow from a clean clone. |
| 28–40 | Publish or package the build, rehearse twice, and capture a backup demo. Freeze scope at hour 40. |
| 40–48 | Fix demo blockers, check submission requirements, and submit. |

If a live integration is unstable at hour 28, use the fixture mode for the demo and disclose the simulation. If hosting is unavailable, rehearse from the local production build and keep the backup recording.

## Completed Features

- Minimal browser starter and shared repository workflow. Product implementation starts after kickoff.
